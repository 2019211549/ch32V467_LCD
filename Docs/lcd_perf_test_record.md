### 3. 与理论对照分析

**【理论推算】** 纯像素负载：153600 B × 8 bit ÷ 6.25 MHz = **196.6 ms/帧**（5.08 FPS）。

**【实测→已验证】** solid ≈196.6 ms，与理论差 **< 0.5%**：
- 6.25 MHz 这档频率下，CPU 轮询完全喂得饱 SPI 总线；
- 当前瓶颈就是 **SPI 带宽本身**，软件发送路径开销可忽略。

**【实测推算】** 窗口命令开销 ≈ **17~18 µs / 窗口**：
- checker 比 solid 多 299 个窗口：201.9 − 196.6 = 5.3 ms → 5.3ms ÷ 299 ≈ **17.7 µs/窗口**
- gray 比 solid 多 29 个窗口：0.5 ms ÷ 29 ≈ 17.2 µs/窗口（两组独立数据吻合）
- 验算：一次窗口 = CASET(5B) + RASET(5B) + RAMWR(1B) + CS/DC 翻转 ≈ 11~13 字节
  @6.25MHz ≈ 14~17 µs + GPIO 操作 → 与实测吻合
- **推论【未验证】**：提频后字节传输时间按比例缩短，但 GPIO/函数调用部分不随频率变；
  阶段2 专门量化软件开销占比。

**【实测】** 每图案 min = max 完全一致：测试跑在调度器启动前、无中断干扰，
计时确定性极高，单次测量即可信（仍保留 10 帧统计习惯，便于以后带 OS 环境对比）。

### 4. 已知测试代码问题（只影响打印，不影响测量数值）

1. **`uart_printf` 不支持 `%-8s`**（`-` 左对齐标志）：该段被原样输出且**不消费参数**，
   导致后面所有参数左移一位。显示↔实际对应关系：
   `n=10072` ← 字符串 "solid" 的地址(0x2758)；`avg=10ms` ← 真正的 n；
   `min=196ms` ← 真正的 avg；`max=196ms` ← 真正的 min；`fps=196.5` 整数部分 ← 真正的 max。
2. **`PERF_THEORY_US` 32 位溢出**：RV32 上 `unsigned long` 是 32 位，
   153600×8×1000000 ≈ 1.23e12 > 2^32，中间乘法溢出 → 打印 "theory = 0ms"。
   正确理论值 196.6 ms（§3 手算）。

处理结果（2026-09-24，**已修复并复测验证**）：
- `bsp_uart.c` 的 `%s` 补上域宽右对齐（根因：原实现忽略宽度且不认 `-`，`%-8s` 原样输出还不消费参数）；测试改用 `%8s`
- 理论宏中间乘法改 64 位（`1000000ULL`），theory 恢复 196.6ms
- 耗时打印加 1 位小数（亚毫秒分辨率，供后续阶段对比）
- 复测数值与修复前还原值完全一致 → 修复未影响测量路径

### 5. 阶段0 结论

- **PASS**：solid 实测 196.6 ms，落在参考带 196~217 ms 内；无花屏 / 卡死 / 死机反馈。
- **基线锚点（后续所有优化的对照组）**：

| 锚点 | 值 |
|---|---|
| 全屏刷新（轮询 @6.25MHz） | **≈197 ms ≈ 5.1 FPS** |
| 窗口命令开销 | **≈17.7 µs/窗口** |
| 总线利用率（solid/理论） | **>99.5%** |

### 100MHz（÷2）实测分析（2026-09-24）

```
[PERF]    solid n=10 avg=12.2ms min=12.2ms max=12.2ms fps=81.3   ← 横幅当时误标 50MHz
[PERF]     bars n=10 avg=12.3ms min=12.3ms max=12.3ms fps=81.2
[PERF]  checker n=10 avg=12.9ms min=12.9ms max=12.9ms fps=76.9
[PERF]     gray n=10 avg=12.3ms min=12.3ms max=12.3ms fps=80.9
```

- **solid 12.2ms = 100MHz 理论地板（12.288ms），利用率 ≈100%**【实测】
  —— **轮询 + SPI16 喂得饱 100MHz 总线**：每像素 160ns 帧周期，CPU 一次
  TXE 轮询+一次寄存器写（约 40-80ns）足够跟上。阶段10 的 16bit 优化在此兑现
  （8bit 轮询需要每 80ns 写一次，必挂）。
- 窗口开销：checker−solid = 0.7ms / 299 = **2.34µs/窗口**
  （11 字节线时间 0.88µs + 软件 ~1.46µs，与 6.25MHz 时的软件量级吻合）。
- min=max 全程无抖动。
- **注意事项**：
  1. 100MHz = PCLK2/2，是 SPI 分频的硬件极限档
  2. 引脚驱动档位 GPIO_Speed_High=50MHz 级，SCK 跑 100MHz 属超规格使用，
     信号完整性靠实测说话——**目视结论待补**
  3. 短测 10 帧不卡死 ≠ 长期稳定；按规格书要求需 soak 后才能定级
  4. 帧间驻留 400ms 观屏已就位（PERF_FRAME_HOLD_MS）
