# LCD 撕裂根治：扫描同步 + 竖板追扫 —— 原理与标定全记录

> 项目：CH32V467RET + P032B017P（ST7789P3，240×320 IPS，4-wire SPI，横屏 320×240）
> 结论先行：**2026-10-16 板证收官——T3 滑动界面全程零撕裂。**
> 方案一句话：面板没有 TE 引脚，就用 GSCAN(0x45) 读扫描位置自制"vsync"，

## 1. 撕裂是什么

LCD 不是"一整屏同时点亮"的设备。面板内部有一个**扫描器**，以固定节拍
逐行（本屏横屏下=逐列）把 GRAM 里的数据推到玻璃上显示。CPU 这边往 GRAM
写数据是另一条异步的流。**当扫描器恰好路过某块区域、而这块区域的数据正
被写到一半时**，这一趟扫出来的画面就一半是新内容、一半是旧内容——两色
交替的翻色实验里表现为一条分界线，滑动界面里表现为一帧错位。

所以撕裂的充要条件非常干净：

> **存在某个像素，它被扫描采样（显示）的时刻，落在它被写入的时间区间内部。**

整个方案的目标就是让这个条件永远不成立——不是"减小撕裂"，是数学上消灭它。

## 2. 面板侧的物理：扫描模型

从 GSCAN 读数（§3）反推出的面板行为，横屏逻辑坐标（U=0..319 从左到右，V=0..239 从上到下）：

```
一趟扫描（16.747ms）：
  ...回绕(计数166→0)... ─Δ≈1.1ms─> 显示第0列 ──52.33µs/列──> 显示第319列 ──> 回绕...
                                      ↑ 每列的 240 个像素在"该列的瞬间"整体采样
```

三个关键量：

- **每列一个显示时刻**：扫描按列（横屏）推进，列内 240 像素视为同一瞬间被采样
  （这一假设被 δ0 阶梯实验的齿形态证实，§4.3）；
- **回绕点 ≠ 可见帧头**：GSCAN 计数回绕之后，还要过 Δ≈1.1ms（≈21 列的时间）
  面板才显示第 0 列——这段是 porch/消隐期。Δ 是"自制 vsync"必须补的相位修正；
- **写一块板的时间 ≈ 扫一块板的时间**：75MHz SPI 写 16 列×240 行要 819µs，
  扫描渡越 16 列要 837µs——两个速度几乎一样，这正是踩过的第一个坑（§4.3）。

## 3. 观察工具：GSCAN(0x45)

ST7789 系列的扫描位置寄存器（本模组 FPC **没焊 TE 引脚**，硬件同步路线
不存在，只能软读）。协议：发 0x45 + 1 个 dummy 时钟，回 2 字节 = 当前扫描行。

**读数可信性用三条独立证据链验证过**（`Test/test_lcd_gscan.c`）：

1. 回绕间隔 = 16741~16750µs，四档读速（/128 ~ /16）测同一周期偏差 0%；
2. 最小二乘斜率（10.28 计数/ms）与周期反推斜率（9.92 计数/ms）偏差 3%；
3. dummy=0 时高 8 位是哑元残留、dummy=1 才是真行号——协议对齐的独立佐证。

量程 0..166、单位疑似 2 行/计数（166×2≈332 行 ≈ 320 可见 + ~12 消隐，
与 Δ≈1.1ms 的量级同向；精确映射对工程无用，不强求）。最快可信读速
/16 分频 ≈ 5µs/次——回绕检出精度 ~5µs，足够（δ0 余量 150µs）。

## 4. 诊断之路：四个关键转折

### 4.1 横带路径的斜线——垂直写入必撕裂的数学证明

原生产路径：LVGL 24 行横带、整屏 10 带轮询/DMA 写。写前缘沿 **V** 方向
推进（16438µs/240 行 = **68.49µs/行**），扫描沿 **U** 方向推进（52.33µs/列）。
两轴垂直，分界线是两个时间前沿的等时线：

```
第 v 行写完的时刻    t_w(v) = 68.49·v
第 u 列显示的时刻    t_s(u) = Δ + 52.33·u
分界线（t_w = t_s）： v = (52.33·u + Δ − δ)/68.49 ≈ 0.764·u + 常数
```

斜率 0.764 —— 一条贯穿整屏的斜线（320×0.764 ≈ 244 ≈ 屏高），**板证观察
与预测完全一致**。关键结论：横带写入下分界线斜率由两个速度比决定，与快慢
无关——**只要写轴 ⊥ 扫轴，撕裂在数学上不可避免**。要根治必须同轴。

### 4.2 扫描方向判别——镜像对角线判别器

怎么确定扫描是从左到右还是从右到左？GSCAN 只给"扫到第几行"，不给方向。
利用 4.1 的斜线做判别器：假设左→右，分界线锚定"左上→右下"；假设右→左，
整条线镜像成"右上→左下"。板证观察：**左上→右下** ⇒ 扫描=左→右。
（理论备选：MADCTL 的 ML 位可翻扫描方向，但翻扫描不如顺应扫描——写入方向
是我们能控制的那一边。）

### 4.3 同轴竖板的第一次失败——"贴身追"的教训

改成 16 列×240 行竖板、与扫描同向、配速 845µs/板（写 52.8µs/列 > 扫
52.33µs/列，"永远追在后面"）——**板证仍然撕裂**：每 16 列一条陡斜线
（左上→右下）。这是整个探索里最有价值的一次失败，它暴露了错误的撕裂模型。

错误模型："每列在本帧显示之后写完、下一帧显示之前就绪 → 干净"。
（推导时把不等式方向弄反了。）

正确机理，逐帧推演 δ0=0 时的一块板：

```
写一块板 819µs，板内数据序 = 行优先（v=0 行的 16 像素最先，v=239 最后）
→ 每一列的 240 个像素"从上到下"摊在这 819µs 里写完（顶底相差 815µs）

扫到板左列时（板刚起写几百 µs）→ 整列旧
扫到板右列时（板快写完）      → 顶部已新、底部还旧  ← "写一半被看见"
分界高度逐列抬升 15.3px/列，16 列跨 245px ≈ 整屏高
→ 每块板内部一条完整的"左上→右下"陡斜线，20 块板 = 20 条
```

**教训**：同方向 + 速度相近 ≠ 不撕裂。写一块板的整段 819µs 期间，扫描
**一步都不能踏进这块板**。这就是"落后一整块板"条件的由来（§5）。

### 4.4 δ0 阶梯标定——人眼当测量仪

竖板起写延迟 δ0（回绕检出后再等多久动笔）从 0 逐档加大，红蓝整屏翻色，
数屏幕左上角的"齿"：

| 轮次 | δ0 | 现象 | 推论 |
|---|---|---|---|
| 3 | 1650 | 左上角 3 个齿 | 撕裂只剩最左 2~3 块板 |
| 3 | 1750 | 左上角 2 个齿 | 齿随 δ0 增大**左移、缩小、减少** |
| 4 | 1850 | 仍有齿 | δ0\* > 1850 |
| 4 | **1950** | **全干净** | **δ0\* ∈ (1850, 1950]** |
| 4 | 2050 / 2000 | 全干净 | 上界方向有巨大余量 |

两个读数：

- **δ0\* ≈ 1900±50µs**——生产取 2100（+150µs 余量盖住抖动 0.14%≈23µs 和检出延迟）；
- **Δ = δ0\* − 785 ≈ 1.1ms**（785 = 扫描显示完板 0 最后一列的时刻，见 §5.4 推导）。

阶梯现象本身也验证了模型：齿只出现在**最左边**几块板（板序越靠后尾随余量
越大），且随 δ0 增大**从右向左退**——与"逐板阈值"的理论方向一致。

## 5. 核心原理：为什么"落后一整块板"就不撕裂

### 5.1 盲窗

对任何一块板 k，时间轴上存在一个巨大的"盲窗"：

```
     趟 m 扫描离开板k                趟 m+1 扫描回到板k
          │◄───────── 约 15.9ms 盲窗 ─────────►│
          │   这段时间里扫描完全不看板k        │
          └── 把 819µs 的写藏进这里即可 ──┘
```

只要写的起止都落在盲窗内，板 k 在趟 m 全旧显示、在趟 m+1 全新显示。

### 5.2 逐像素证明

设板 k 起写时刻 L(k)，写完时刻 L(k)+819；扫描趟 m 显示板 k 各列的区间为
[Δ+837.3k, Δ+837.3k+785]，趟 m+1 为其 +T_scan。无撕裂条件：

```
(1) L(k) ≥ Δ + 837.3k + 785        写开始 ≥ 本趟显示完板k（否则撞上"写一半"）
(2) L(k) + 819 < T_scan + Δ + 837.3k   写结束 ≤ 下趟进入板k（否则还是旧的，错帧）
```

板 k 的像素 (j, v) 被采样时：写完成时刻在采样之前（全新）或之后（全旧），
二选一，不存在中间态 ⇒ **无撕裂的充要条件成立**。

### 5.3 帧量化 = 自制 vsync 页翻转

条件 (1)(2) 对全部 20 块板同时成立时，一趟扫描显示的是**完整的旧帧**，
下一趟是**完整的新帧**——整屏内容在扫描趟边界**统一翻转**。这正是 PC 显卡
vsync + 页翻转（page flip）的语义，只不过"vsync 信号"是我们用 GSCAN 回绕
检测自己造的，"页"是 PSRAM 里的 staging 整帧。翻色实验表现为整屏干净变色，
滑动 UI 表现为无错位。

### 5.4 参数推导与安全窗

- **下界**：板 0 最苛刻，L(0) ≥ Δ+785 ⇒ δ0 ≥ 785+Δ ≈ 785+1115 ≈ 1900，
  板证 δ0\*=1950 与理论吻合（差值 = 检出延迟 + 观察阈值）；
- **上界**：板 19 的条件 (2)：δ0 + 19·pace + 827 < T_scan + Δ + 19·837.3
  ⇒ δ0 ≲ 16000µs。安全窗 **[1950, 16000]**，取 2100 离两边都有 >10ms 量级余量；
- **配速**：pace 必须 ≥ 每板写时长 827µs（否则板间追赶），且 ≥ 扫描槽位
  837.3µs（否则尾随量逐板缩小，20 板累计丢掉 200µs 余量）→ 取
  **845µs**（= T_scan/20 + 8）。注意 pace 是**下限**不是上限：哪块板写慢了
  只会更落后、更安全（上界兜底），代价只是帧周期变长。

```
δ0=2100 时的安全账（最坏板 0 与板 19）：
  板 0 尾随 = 2100 − (Δ1115+785) = 200µs > 0        （不撞"写一半"）
  板19 收笔 = 2100+19×845+827 ≈ 19.5ms
            << T_scan+Δ+19×837.3 ≈ 33.8ms            （赶得上下一趟）
```

### 5.5 为什么是 16 列宽

- DMA 单笔 32768 半字上限内（16×240=3840 ✓），一块板一笔 DMA；
- SRAM 乒乓板 2×7.68K = 15.4K，放得下；
- 每帧 20 个窗口，窗口命令开销 ~8µs/板（摊 0.5µs/列，可忽略）；
- 更窄（如 1 列）尾随可以更短，但窗口开销 ×20 倍；更宽则 SRAM 涨、δ0 下界
  （785→N×52.33）同步涨。16 列是权衡点，非理论最优。

## 6. 生产实现（`Bsp/bsp_lcd_scan.c` + `bsp_lvgl_port.c` 竖板模式）

### 6.1 数据通路

```
LVGL 部分刷新（15K SRAM 画布，24 行横带，与面板扫描轴垂直——渲染轴无所谓，
              撕裂只看最终上屏的那条流）
   │ flush_cb 逐带 bsp_lcd_scan_band_put()
   ▼
PSRAM 整帧 staging（窗口 +0x80000，150K，行主序）
   │  兼任"持久帧缓冲"：脏区外内容自动保序；无脏区 = 不追扫 = 零成本
   │  帧末 lv_display_flush_is_last()
   ▼
bsp_lcd_scan_frame_send()
   ├─ 等 GSCAN 回绕（自制 vsync；忙等 ≤16.7ms）
   ├─ δ0 = 2100µs
   └─ 20 板流水：
        gather 板0 → ┌ DMA 写板 k（819µs）┐ ← SPI，尾随扫描一整板
                     │ CPU gather 板 k+1  │ ← PSRAM→SRAM 乒乓板，
                     └────────┬──────────┘   藏在 DMA 的 819µs 里
                              ▼
                    下一板（配速 845µs 下限）
```

### 6.2 三个工程决策的出处

- **staging 放 PSRAM**：SRAM 135K 放不下 150K 整帧；PSRAM 实测写 42/读
  41MB/s，远大于 SPI 的 9.375MB/s，只做搬运不参与渲染（T4 教训：让 LVGL
  直接往 PSRAM 渲染 = 36ms/帧，太慢）；
- **gather 重打包**：LVGL 画布是行主序横带，竖板 DMA 需要列连续数据，
  240 行 × 32B 的碎读聚成 16×240 连续块——PSRAM 带宽下整个隐藏在 DMA
  带宽的影子里（串口心跳行 `gather/帧` 实测）；
- **回退梯子**：PSRAM 自检不过 / GSCAN 无应答 → 自动回退 24 行横带部分
  刷新（显示照常，撕裂回到斜线形态，判定行 `slab=0` 标出）—— degraded
  but alive。

### 6.3 验收（板证 2026-10-16）

- T3 三页横滑 + 3s 自动演示：**全程无斜线、无齿、无错位**；
- 判定行：`帧N 追扫avg Xms max Yms gather/帧Zus 超时0`，`slab=1`；
- 手感：~30fps 上限（整屏更新周期 2 帧）——这是零撕裂的固定代价，
  静态界面（PSG 波形页）无脏区不追扫，不受影响。

## 9. 可迁移的工程启示

1. **先给"不可能"立项**：横带撕裂不是 bug 是几何——证明"此路不通"和找到
   新路同样重要（v=0.764u 的推导直接终结了在横带路径上继续调参的幻想）；
2. **失败的实验往往在纠正模型**：δ0=0 的斜纹推翻了"列完整即可"的错误条件，
   换来"板级盲窗"的正确条件——现象与理论的每一次吻合都是模型可信度的积累；
3. **没有硬件信号就造一个**：TE 缺失 → GSCAN 轮询自制 vsync，精度 5µs
   足够（余量 150µs）；
4. **人眼是合法的测量仪**：翻色 + 阶梯把"相位差 Δ"这种无法用逻辑分析仪
   方便观测的量，变成可数的齿；
5. **参数要标定不要推导**：Δ 的理论外推（~650µs）与实测（~1.1ms）差近
   一倍——porch 结构、检出延迟等现实因素只有板子知道；最终参数一律以
   板证为准，理论只用来圈定搜索范围；
6. **安全窗思维**：δ0 不是单点而是 [1950, 16000] 的窗口，配速是下限不是
   上限——把"必须精确"的问题改写成"只要落在窗内"，鲁棒性来自结构而非精度。
