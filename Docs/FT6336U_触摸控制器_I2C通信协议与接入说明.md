# FT6336U 触摸控制器 I²C 通信协议与 STM32 接入说明

> 文档版本：V1.0  
> 适用项目：STM32U703 + FreeRTOS + LVGL（9 及后续版本）+ 3.2 英寸 TFT 触摸屏  
> 屏幕型号：`P032B017P-IPS-CTP`  
> 触摸控制器：`FT6336U`  
> 显示控制器：`ST7789P3`

## 0. 资料来源与使用边界

本文依据以下**两份已提供资料**整理：

1. **屏幕规格书**：深圳市 P&O Technology，`P032B017P-IPS-CTP`，Rev. A，2024-11-18。重点参考第 2 页（显示/触摸 IC）及第 3 页（FPC 引脚）。
2. **芯片规格书**：FocalTech，*FT6336U Self-Capacitive Touch Panel Controller*，Preliminary Datasheet V1.0（2015）。重点参考正文第 1–7 页（功能、I²C、电气参数、上电复位时序）。

**重要的证据边界：**

- FT6336U 芯片规格书明确给出 I²C 电气/传输格式、触摸及手势能力，但**没有提供完整的主机寄存器映射表**。
- 文中的 `0x00`、`0x01`、`0x02`、`0x03` 等寄存器及手势值，来自**常用 FT6x36 系列兼容协议约定**，属于驱动开发参考，**不能仅凭上传的 FT6336U Preliminary Datasheet 确认适用于每一种模组固件**。使用前应以实物通信验证、模组厂补充协议或具体固件手册为准。
- 下文的 `0x38` 为常见 7 位 I²C 地址，亦应以实际 I²C 探测结果为准。不要把系列兼容协议当作该模组已验证的行为。

## 1. 芯片能力概览

FT6336U 是基于**自电容（Self-Capacitive）**检测技术的触摸控制器，内部集成增强型 16 位 MCU、模拟前端（AFE）、ADC、滤波和电容变化检测逻辑。主控不必自行采样原始电极信号，而是通过 I²C 获取经处理的触摸信息。

| 参数 | 说明 | 依据 |
|---|---|---|
| 触摸技术 | 自电容 | FT6336U 手册 Introduction / Features |
| 触摸能力 | 单点及手势，或最多两点 | FT6336U 手册 Features；实际模式取决于固件 |
| 内置处理器 | 16 位增强型 MCU | FT6336U 手册 Introduction |
| 传感通道 | 最多 39 个 | FT6336U 手册 Features |
| 主机接口 | I²C 从设备接口 + INT + RSTN | FT6336U 手册 §2.4 |
| I²C 时钟 | 10–400 kHz | FT6336U 手册 Table 2-2 |
| 报告率 | 最高 100 Hz | FT6336U 手册 Features |
| 默认扫描率 | Active：60 帧/秒；Monitor：25 帧/秒 | FT6336U 手册 §2.3 |
| 芯片工作电源 | VDDA / VDD3：2.8–3.3 V（数据手册 DC 表） | FT6336U 手册 Table 3-2 |
| I/O 电平电源 | IOVCC 为独立供电域，电压约束见芯片手册 | FT6336U 手册 §3.1–3.2 |

> 注意：显示屏 **ST7789P3 走 SPI**，触摸屏 **FT6336U 走 I²C**，两套接口彼此独立。屏幕模组实际触摸 VDD、I/O 电平是否已做内部连接或电平处理，需要结合电路图确认；不能仅按芯片绝对最大值决定供电。

## 2. 硬件接口与连接

### 2.1 触摸 FPC 引脚定义

屏幕规格书第 3 页给出的 **Touch FPC 6 Pin** 如下：

| FPC 引脚号 | 引脚名称 | 功能 | STM32U703 建议连接 |
|---:|---|---|---|
| 1 | `CTP_RST` | 触摸芯片复位 | GPIO 推挽输出 |
| 2 | `CTP_INT` | 触摸通知信号 | GPIO 外部中断输入（EXTI） |
| 3 | `CTP_SDA` | I²C 数据 | `I2C_SDA` |
| 4 | `CTP_SCL` | I²C 时钟 | `I2C_SCL` |
| 5 | `GND` | 地 | 系统 GND |
| 6 | `VDD` | 触摸供电 | 按模组电源规格接入 |

### 2.2 硬件设计要点

- **SDA/SCL**：I²C 为开漏通信，按实际 I/O 电压域配置合适的上拉电阻；不要机械地将触摸 I/O 拉至 STM32 的 3.3 V，先确认模组电平兼容性。
- **RST**：芯片复位输入低有效（`RSTN`）。
- **INT**：用于向主控报告有触摸数据可读取；触发极性、脉冲/电平行为和报告模式需结合固件验证。
- **公共地**：STM32 和触摸模组必须共地。
- **DMA**：触摸数据量少，通常采用 I²C 中断或短时阻塞读取即可；不需要为触摸单独配置 DMA。

## 3. 通信层：I²C 协议

### 3.1 主从关系、地址与速率

- **STM32U703：I²C Master**。
- **FT6336U：I²C Slave**（芯片手册 §2.4.1 明确规定）。
- 常见 **7 位地址**为 `0x38`。
- 标准 I²C 总线在传输地址后带一位 `R/W`：
  - 写地址字节：`0x70`（`0x38 << 1 | 0`）；
  - 读地址字节：`0x71`（`0x38 << 1 | 1`）。
- STM32 HAL I²C API 的 `DevAddress` 通常需要填写**左移一位**的设备地址：`0x38 << 1`。
- 支持时钟范围为 **10–400 kHz**；建议首次调试采用 **100 kHz**，通信稳定后再按需要提高至 **400 kHz**。

```c
#define FT6336U_I2C_ADDR_7BIT  0x38U
#define FT6336U_HAL_ADDR       (FT6336U_I2C_ADDR_7BIT << 1)
```

### 3.2 I²C 基本符号

| 符号 | 含义 |
|---|---|
| `S` | START 起始条件 |
| `Sr` | Repeated START 重复起始 |
| `P` | STOP 停止条件 |
| `W` | 主机向从机写入 |
| `R` | 主机从从机读取 |
| `ACK` | 接收方应答 |
| `NACK` | 接收方非应答；连续读操作的末字节可由主机发出 NACK |

> 上传的芯片手册给出了 I²C 字节传输及主写/主读示意；并**没有规定专用报文头、长度域或 CRC 校验尾部**。应用层按寄存器访问组织读写，不要额外加自定义 CRC。

### 3.3 单寄存器读取（兼容寄存器访问方式）

一般先写目标寄存器地址，再重复起始切换为读：

```text
S -> [0x70: W] -> ACK -> [REG] -> ACK
  -> Sr -> [0x71: R] -> ACK -> [DATA] -> NACK -> P
```

例如读取手势寄存器（兼容协议中 `REG = 0x01`）：

```text
START -> 0x70 -> ACK -> 0x01 -> ACK
RESTART -> 0x71 -> ACK -> GEST_ID -> NACK -> STOP
```

### 3.4 连续读取多个寄存器

假设起始地址为 `0x02`，要读取 `N` 字节：

```text
S -> 0x70 -> ACK -> 0x02 -> ACK -> Sr -> 0x71 -> ACK
  -> DATA[0] -> ACK -> DATA[1] -> ACK -> ...
  -> DATA[N-1] -> NACK -> P
```

此操作依赖目标固件支持连续地址读取；建议用逻辑分析仪核对首包及实际返回值。

### 3.5 STM32 HAL 示例

```c
#include "stm32u7xx_hal.h"
#include <stdint.h>

#define FT6336U_ADDR          (0x38U << 1)
#define FT6336U_REG_TD_STATUS 0x02U

extern I2C_HandleTypeDef hi2c1;

HAL_StatusTypeDef ft6336_read_regs(uint8_t reg, uint8_t *buf, uint16_t len)
{
    if (buf == NULL || len == 0U) {
        return HAL_ERROR;
    }

    return HAL_I2C_Mem_Read(&hi2c1,
                            FT6336U_ADDR,
                            reg,
                            I2C_MEMADD_SIZE_8BIT,
                            buf,
                            len,
                            100U);
}
```

> 说明：`hi2c1` 是示例句柄，替换成实际使用的 I²C 外设；若项目使用 `HAL_I2C_Mem_Read_IT()`，还需编写完成/错误回调并保证读缓冲区在传输期间有效。

## 4. 常见 FT6x36 兼容寄存器映射（需实机核验）

**以下表格并非上传 FT6336U 初版数据手册的直接内容**，用于常见 FT6x36 兼容驱动实现，模块固件可能有差异。

| 地址 | 常见名称 | 说明 |
|---|---|---|
| `0x00` | `DEV_MODE` | 设备模式 |
| `0x01` | `GEST_ID` | 手势代码 |
| `0x02` | `TD_STATUS` | 当前有效触点数量（一般使用低 4 位） |
| `0x03` | `P1_XH` | 触点1：事件标志及 X 高位 |
| `0x04` | `P1_XL` | 触点1：X 低 8 位 |
| `0x05` | `P1_YH` | 触点1：ID 及 Y 高位 |
| `0x06` | `P1_YL` | 触点1：Y 低 8 位 |
| `0x07` | `P1_WEIGHT` | 触点1：权重/压力相关字段（依固件） |
| `0x08` | `P1_MISC` | 触点1：其他信息 |
| `0x09` | `P2_XH` | 触点2：事件标志及 X 高位 |
| `0x0A` | `P2_XL` | 触点2：X 低 8 位 |
| `0x0B` | `P2_YH` | 触点2：ID 及 Y 高位 |
| `0x0C` | `P2_YL` | 触点2：Y 低 8 位 |
| `0x0D` | `P2_WEIGHT` | 触点2：权重字段 |
| `0x0E` | `P2_MISC` | 触点2：其他信息 |
| `0xA4` | `G_MODE` | 中断/报告模式配置；**不是“手势识别使能”** |
| `0xA5` | `PWR_MODE` | 电源模式 |
| `0xA6` | `FIRMID` | 固件版本号 |

### 4.1 触点数据字节结构

常见解析方式：

```text
P1_XH (0x03)
 bit7:6  EVENT_FLAG   事件状态
 bit5:4  RESERVED
 bit3:0  X[11:8]     X 高 4 位

P1_XL (0x04)
 bit7:0  X[7:0]      X 低 8 位

P1_YH (0x05)
 bit7:4  TOUCH_ID     触点 ID
 bit3:0  Y[11:8]     Y 高 4 位

P1_YL (0x06)
 bit7:0  Y[7:0]      Y 低 8 位
```

坐标计算：

```c
uint16_t x = ((uint16_t)(p1_xh & 0x0FU) << 8) | p1_xl;
uint16_t y = ((uint16_t)(p1_yh & 0x0FU) << 8) | p1_yl;

uint8_t event    = (p1_xh >> 6) & 0x03U;
uint8_t touch_id = (p1_yh >> 4) & 0x0FU;
```

常见 `EVENT_FLAG` 编码如下：

| 编码 | 含义 |
|---:|---|
| `0` | Press Down：按下 |
| `1` | Lift Up：抬起 |
| `2` | Contact：持续接触 |
| `3` | No Event：无事件 |

### 4.2 一次读取最多两点坐标

从 `0x02` 连续读取 11 字节，可覆盖 `TD_STATUS`、第一点和第二点的 X/Y 坐标字段：

```c
uint8_t raw[11] = {0}; // 0x02 ~ 0x0C

if (ft6336_read_regs(0x02U, raw, sizeof(raw)) == HAL_OK) {
    uint8_t count = raw[0] & 0x0FU;
    if (count > 2U) {
        // 数据异常：当前驱动只允许最多 2 点
        count = 0U;
    }

    if (count >= 1U) {
        uint8_t p1_xh = raw[1];  // 0x03
        uint8_t p1_xl = raw[2];  // 0x04
        uint8_t p1_yh = raw[3];  // 0x05
        uint8_t p1_yl = raw[4];  // 0x06

        uint16_t x1 = ((uint16_t)(p1_xh & 0x0FU) << 8) | p1_xl;
        uint16_t y1 = ((uint16_t)(p1_yh & 0x0FU) << 8) | p1_yl;
        uint8_t evt1 = (p1_xh >> 6) & 0x03U;
        uint8_t id1 = (p1_yh >> 4) & 0x0FU;
        (void)x1; (void)y1; (void)evt1; (void)id1;
    }

    if (count >= 2U) {
        uint8_t p2_xh = raw[7];  // 0x09
        uint8_t p2_xl = raw[8];  // 0x0A
        uint8_t p2_yh = raw[9];  // 0x0B
        uint8_t p2_yl = raw[10]; // 0x0C

        uint16_t x2 = ((uint16_t)(p2_xh & 0x0FU) << 8) | p2_xl;
        uint16_t y2 = ((uint16_t)(p2_yh & 0x0FU) << 8) | p2_yl;
        uint8_t evt2 = (p2_xh >> 6) & 0x03U;
        uint8_t id2 = (p2_yh >> 4) & 0x0FU;
        (void)x2; (void)y2; (void)evt2; (void)id2;
    }
}
```

> 触点数量为 0 时要向 LVGL 报告 `RELEASED`；触点数量及事件、ID 字段应综合判断，避免多指切换时把第一点错认成同一根手指。

## 5. 手势能力与手势寄存器

### 5.1 芯片手册能够确认的能力

FT6336U 芯片手册在 **Introduction/Features** 明确提到：支持**单点触摸及手势**，或者**两点触摸**。但所提供手册**未列出具体手势类型、编码表、算法门限及固件启用条件**。

### 5.2 常见 FT6x36 兼容手势值（参考，需验证）

| `GEST_ID` 值 | 典型定义 |
|---|---|
| `0x00` | 无手势 |
| `0x10` | 向上滑动 |
| `0x14` | 向右滑动 |
| `0x18` | 向下滑动 |
| `0x1C` | 向左滑动 |
| `0x48` | 放大手势（Zoom In） |
| `0x49` | 缩小手势（Zoom Out） |

这些是**兼容协议常见值**，并不保证特定 FT6336U 固件一定上报。例如 `GEST_ID` 始终为 `0x00`，也不妨碍主机基于坐标序列判断滑动方向。

### 5.3 芯片识别与主控/LVGL 识别的区别

| 方案 | 数据输入 | 优点 | 限制 |
|---|---|---|---|
| 芯片固件手势 | `GEST_ID`（若固件支持） | MCU 处理负担小 | 是否启用、编码行为需确认 |
| LVGL/主控软件手势 | 触摸状态、坐标、时间序列 | 行为可控，可调灵敏度 | 需要连续、稳定的触摸数据 |

**建议**：UI 的点击、拖拽、长按和方向滑动优先交给 LVGL；只有确认当前固件能稳定返回手势 ID 时，才将其作为额外输入。双指缩放需先验证模组是否稳定上报两个独立触点，再另行设计适配逻辑。

## 6. 芯片运行模式与复位时序

### 6.1 工作模式（FT6336U 手册 §2.3）

| 模式 | 功能 |
|---|---|
| `Active` | 正常扫描与上报，默认约 60 帧/秒 |
| `Monitor` | 低速检测，默认约 25 帧/秒；该模式下手册描述串口关闭，不进行主机通信；检测到触摸后返回 Active |
| `Hibernation` | 极低功耗休眠，通过主机复位或唤醒信号恢复 |

### 6.2 复位及上电要求

依据芯片手册 **Table 3-5**：

| 参数 | 手册限制 | 说明 |
|---|---|---|
| `Trst` | 至少 5 ms | RESET 低电平保持时间 |
| `Tpon` | 至少 300 ms | 上电到开始报告触摸点的时间 |
| `Trsi` | 至少 300 ms | 复位到开始报告触摸点的时间 |
| `Tprt` | 至少 1 ms | 上电后复位低电平保持要求 |

主控初始化建议：供电稳定 → `RST` 拉低至少 5 ms → `RST` 拉高 → 等待至少 300 ms 后尝试读取寄存器。具体 GPIO 上电默认电平及 INT 配合时序，应对照板级电路、实测信号进行确认。

## 7. 接入 FreeRTOS + LVGL 的软件架构

```text
             ┌─────────────────┐
             │  FT6336U 触摸层  │
             └───────┬─────────┘
                   INT / I²C
                     │
             ┌───────▼─────────┐
             │ STM32U703 / EXTI │
             │ ISR 仅设置标志位 │
             └───────┬─────────┘
                     │
             ┌───────▼─────────┐
             │ FreeRTOS task_ui │
             │ 读取/更新触摸态  │
             └───────┬─────────┘
                     │
             ┌───────▼──────────┐
             │ LVGL indev read_cb│
             │ PRESSED/RELEASED  │
             └──────────────────┘
```

推荐约束：

1. **不单独开触摸线程**：UI 任务统一维护 LVGL 及触摸数据读取，优先避免跨线程调用 LVGL。
2. **EXTI 中断不直接做 I²C 读写**：中断里只置标志/通知任务，实际读取在任务上下文进行。
3. **不能只依赖一次 INT 边沿**：按住、拖动、抬起期间需保证状态持续更新；根据模组的 INT 行为决定是否采用额外周期轮询。
4. **I²C 读取失败时处理状态机**：合理重试，避免卡住 UI，也不能让 LVGL 长时间停留在虚假的 `PRESSED` 状态。
5. **坐标必须校准和旋转**：屏幕模组原生为 `240 × 320`，横屏 LVGL 为 `320 × 240`，旋转方向应与当前 LCD 驱动保持一致。

### 7.1 坐标旋转示例

原始触摸逻辑宽高 `W = 240`、`H = 320`，旋转到 `320 × 240` 时，常见两种关系：

```c
// 旋转到横屏的一个方向
x_lvgl = 319U - y_raw;
y_lvgl = x_raw;

// 相反方向
x_lvgl = y_raw;
y_lvgl = 239U - x_raw;
```

**只选与显示方向一致的一个变换**，并确认原始坐标原点、XY 是否互换，不能照抄后不测试。

### 7.2 LVGL 9+ 接口说明

LVGL 9 及后续版本推荐使用：

```c
lv_indev_t *indev = lv_indev_create();
lv_indev_set_type(indev, LV_INDEV_TYPE_POINTER);
lv_indev_set_read_cb(indev, ft6336_lvgl_read_cb);
```

`ft6336_lvgl_read_cb` 是**需要自行实现**的回调，职责是从缓存或 I²C 得到坐标，再写入 `lv_indev_data_t` 的 `point` 和 `state` 字段。

> 不要使用 LVGL 8 的旧式 `lv_indev_drv_t` 初始化结构体；不同 LVGL 大版本接口不兼容。

## 8. 上板验证顺序

- [ ] **电源和上拉**：核对触摸 VDD、SCL/SDA 电平、电阻及共地；示波器检查供电及波形。
- [ ] **I²C 地址**：首先探测常见 `0x38`，若无响应，确认时序、电平、RST 后再依据模组资料排查其他地址。
- [ ] **读取版本**：尝试读取兼容寄存器 `0xA6`，记录返回值（不把单次读出当作芯片身份的唯一证据）。
- [ ] **单指坐标**：从 `0x02` 读取触摸点数及 `P1_*`，确认 4 个角点与中心点坐标。
- [ ] **按下与松开**：观察事件变化与 `TD_STATUS`，确保不会出现“松开后仍按下”。
- [ ] **双指**：观察 `TD_STATUS` 是否可稳定报告 2，验证两个触点的 ID 与坐标。
- [ ] **手势**：读取兼容寄存器 `0x01`，观察滑动、缩放时是否返回预期编码。
- [ ] **中断模式**：用逻辑分析仪确认 INT 极性、保持时间、上报频率；必要时引入任务轮询。
- [ ] **LVGL**：校准横屏方向，测试按钮、拖拽、列表滚动及连续快速点击。

## 9. 常见问题

**Q1：为什么显示正常，但触摸一直读不到？**  
显示和触摸是不同芯片、不同总线。先查触摸电源、I²C 上拉、设备地址、复位时序，再检查触摸排线是否接好。

**Q2：能否读取手势 ID 直接操作页面？**  
可以尝试，但 `GEST_ID` 编码和上报行为必须先实测。项目建议优先让 LVGL 基于坐标识别基础手势。

**Q3：触摸要使用 DMA 吗？**  
通常不需要。FT6336U 每次读取的数据很少，与 LCD SPI 连续刷图的 DMA 场景不同。

**Q4：要单独创建 `task_touch` 吗？**  
当前项目已有 `task_ui`，一般没有必要。单一 UI 任务更利于维护 LVGL 对象访问和触摸状态一致性。

**Q5：能否实现双指缩放？**  
芯片具备最多两点触摸的能力，但实际固件是否开放稳定双点报告、缩放手势 ID 和相关配置，需要对当前屏幕模组实测。LVGL 的普通指针输入不等于自动具备双指缩放 UI，双点数据通常还需额外接入或自行处理。

## 10. 参考资料与核验结论

### A. 上传资料直接证实的内容

- **屏幕规格书**：`P032B017P-IPS-CTP`，触摸控制器 `FT6336U`，显示控制器 `ST7789P3`；Touch FPC 的 `RST/INT/SDA/SCL/GND/VDD` 引脚顺序。
- **FT6336U 芯片规格书**：自电容架构、单点手势/双点能力、I²C 从设备协议、I²C 10–400 kHz、三种工作模式、上电/复位时序、电源特性。

### B. 需要额外验证的兼容协议内容

- `0x38` 地址及备选地址；
- `GEST_ID`、`TD_STATUS`、`P1_*`、`P2_*`、`FIRMID` 等寄存器及对应含义；
- `0x10/0x14/0x18/0x1C/0x48/0x49` 手势枚举；
- `G_MODE` 的具体写入值、触发极性和中断行为；
- 当前模组固件是否支持同时双点、硬件手势及低功耗唤醒。

**工程结论：** 先验证 I²C 通信和触点坐标，再适配 STM32U703 和 LVGL；将硬件手势码作为可选增强功能，而不是基础输入功能的前置依赖。
